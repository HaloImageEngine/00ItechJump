In Next.js , Give a paragraph for each of the render strategies SSR (Server-Side Rendering) SSG (Static Site Generation) ISR (Incremental Static Regeneration) CSR (Client-Side Rendering)

Next.JS 1) Server-Side Rendering (SSR) in Next.js generates the HTML for a page on the server for every incoming request. When a user requests a page, the server fetches the required data, renders the React components into HTML, and sends the fully populated page to the browser. This approach ensures that users and search engines receive up-to-date content immediately, making it ideal for dynamic, personalized, or frequently changing data. The tradeoff is increased server load and slightly slower response times compared to static pages. 2)Static Site Generation (SSG) in Next.js pre-renders pages at build time, producing static HTML files that can be served directly from a CDN. Because the content is generated ahead of time, pages load extremely fast and scale very well with high traffic. SSG is best suited for content that does not change often, such as marketing pages, blogs, or documentation, but it requires a rebuild and redeploy whenever the underlying data changes.  3)Incremental Static Regeneration (ISR) combines the performance benefits of static generation with the flexibility of server rendering. Pages are initially generated as static HTML, but Next.js can re-generate them in the background after a specified revalidation interval when new requests come in. This allows content to stay reasonably fresh without rebuilding the entire site, making ISR ideal for pages that change occasionally but still need the speed and scalability of static delivery. 4)Client-Side Rendering (CSR) in Next.js renders pages entirely in the browser after the initial JavaScript bundle is downloaded. The server typically sends a minimal HTML shell, and data is fetched on the client using hooks or effects once the page loads. CSR is useful for highly interactive, user-specific experiences such as dashboards or internal tools, but it can result in slower initial load times and weaker SEO compared to server-rendered or statically generated pages.
