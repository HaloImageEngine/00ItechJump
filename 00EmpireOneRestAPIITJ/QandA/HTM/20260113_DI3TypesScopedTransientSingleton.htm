Explain Dependency Injection (DI) lifetime scopes (Transient / Scoped / Singleton)?

Dependency Injection (DI) lifetime scopes define how long a service instance lives and how often a new instance is created within an application. A Transient lifetime creates a new instance of the service every time it is requested, making it suitable for lightweight, stateless services but potentially increasing resource usage if overused. A Scoped lifetime creates one instance per request or logical operation scope (commonly an HTTP request in web applications), ensuring that all components involved in that request share the same instance, which is ideal for services that manage request-specific data such as database contexts. A Singleton lifetime creates a single instance of the service for the entire lifetime of the application, meaning the same instance is shared across all requests and users; this is efficient for services that are expensive to create or hold shared configuration or caching data, but it must be implemented carefully to avoid thread-safety issues and unintended shared state. Together, these lifetimes allow developers to balance performance, memory usage, and data consistency by choosing the appropriate scope for each service type.
